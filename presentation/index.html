Как читать матрицы

  • verticalWalls[r][c] == 1 — стена справа от клетки (r,c).
  • horizontalWalls[r][c] — стена снизу.
  • Последний столбец и последняя строка — внешняя граница; верхнюю и левую границу дорисовывает UI.

canGo: единственная точка проверки перехода

  • dr/dc определяют направление; для каждого — своя матрица и проверка границы.
  • Если переход не соседний или упирается в стену — false.
  • openNeighbors использует canGo; на нём стоят BFS и тесты.

Как это связано дальше

  • BFS и агент вызывают canGo, поэтому не знают о файлах и UI.
  • MazeUiMapper переводит Position в UiPoint и линии для Canvas.
  • MazeModelTest: 7 проверок границ и открытых соседей.

PART 2 · ГЕНЕРАЦИЯ

Part 2: алгоритм Эллера — идея

Эллер строит идеальный лабиринт построчно: клетки объединяются в множества, а стены убираются только между разными множествами.

01
МножестваКаждая клетка начинает в своём множестве. Одинаковый номер = клетки уже соединены.
02
Правые стеныИдём по строке: если соседи из разных множеств, случайно убираем стену и сливаем множества. Между своими — нельзя, иначе появится петля.
03
Проходы внизСлучайно открываем нижние стены, но проверяем: у каждого множества должен остаться хотя бы один проход вниз.
04
Новая строкаКлетки без прохода вниз получают новые номера множеств. В последней строке просто сливаем все множества вправо.
AABBCC
убираем стену между A и B → A A A B C C
AAABCC
Почему идеальныйРовно N−1 проход, нет циклов (стены рвём только между разными множествами), все клетки достижимы (каждое множество получает выход вниз, последняя строка всё сливает).
N−1проходов ровно
1связная компонента
0циклов
O(N)доп. память под sets
Для 1×1 алгоритм тоже работает: цикл по строкам не выполняется, возвращается одна клетка.

Вопросы, которые могут задать

Короткие ответы, которые стоит держать в голове. Если нужен код — вернитесь к слайду с этим файлом.

1. Почему Q-learning, а не BFS?
ТЗ требует RL. Агент учится по наградам; BFS — только эталон в тестах и отдельный решатель Part 3.
2. Как гарантируется кратчайший путь?
Шаг −1, финиш 0 → максимизация Q = минимизация шагов. На 10×10 маршрут сверен с BFS; на 20×20 все 400 стартов нашли выход.
3. Почему старт случайный?
Чтобы покрыть все состояния: требование «из любой начальной точки». В тестах проверены все клетки.
4. Что если финиш недостижим?
Обучение не падает; pathToEnd возвращает пустой список, UI пишет ошибку. Есть отдельный тест.
5. Почему таблица, а не нейросеть?
Дискретное пространство до 50×50, 4 действия. Таблица проще, детерминированнее и не требует RL-библиотек.
6. Как фиксируется лабиринт и финиш?
Оба — val в конструкторе QLearningAgent. Новый лабиринт в UI сбрасывает агента; переобучение создаёт нового.
7. Где валидация?
Файл — repository/mapper; UI — экраны; HTTP — WebServer (400); домен — require. См. отдельный слайд.
8. Как связаны desktop и web?
Оба идут через GameInterface/GameService. Веб не дублирует алгоритмы: JS только рисует и вызывает API.
9. Почему Эллер даёт идеальный лабиринт?
N−1 проход, стены рвём только между разными множествами (нет петель), у каждого множества есть выход вниз (нет изоляции).
10. Как считаются клетки за границей пещеры?
Они живые: aliveNeighbours добавляет 1 за каждую клетку вне поля. Отсюда 5 соседей у угла и 3 у края.
